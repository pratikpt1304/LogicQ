# LogicQ — Application Security Audit Report (Phases 3 & 4)

> **Audit Scope & Safety Declaration**:  
> - All security testing was performed strictly against the local development / test environment (`localhost:5000`, SQLite test database, and Firestore security rules unit evaluator) using synthetic test identities. Zero production student data or external college systems were touched.  
> - All Proofs of Concept (PoCs) are preserved strictly as defensive Vitest assertions in [`server/tests/security-audit-regressions.test.ts`](../server/tests/security-audit-regressions.test.ts), [`server/tests/firestore-security-rules.test.ts`](../server/tests/firestore-security-rules.test.ts), and [`server/tests/judge-malicious.test.ts`](../server/tests/judge-malicious.test.ts).  
> - Every finding marked **FIXED** below has a passing automated retest. Items requiring external GCP/Firebase Console provisioning are explicitly marked **BLOCKED (Manual Step Required)**. LogicQ enforces defense-in-depth controls, but **does not claim to be "fully secure."**

## 2. Coverage Across All 12 Required Audit Categories

1. **Authentication & Sessions (`Cat 1`)**: Verified email/Google auth, institutional domain restriction (`ALLOWED_EMAIL_DOMAINS`) on both `/register` and `/google`, `HttpOnly` + `SameSite=Lax` cookies, live DB check for `isBanned` and `role`, refresh token revocation on logout/ban/role-change/password-reset, `POST /api/auth/logout-all`, and 30-minute shared-lab idle timeout. (`auth.test.ts` + `SA-02` + `SA-04` passing).
2. **Authorization & IDOR (`Cat 2`)**: Verified student vs. admin route separation (`requireRole('ADMIN')`), blocked cross-student submission read (`SA-01`), blocked hidden test case reads on `/api/problems` and `/api/problems/:slug` (`problem.test.ts`), and blocked public email exposure on `/api/users/profile/:username`.
3. **Firestore Rules (`Cat 3`)**: Verified deny-by-default rules (`firestore.rules`) against 8 automated adversarial test cases in `firestore-security-rules.test.ts` (blocking client score tampering, role self-promotion, hidden test reads, peer submission reads, submission deletion, and audit log tampering).
4. **Input Handling, XSS & CSP (`Cat 4`)**: Enforced `256kb` request body limit, `64KB` `code`/`stdin` caps, `http(s)://` validation on `avatarUrl`, HTML tag stripping on profile fields, and Monaco-compatible `Content-Security-Policy` (`SA-03`, `SA-07`).
5. **Judge & Sandbox (`Cat 5`)**: Verified isolated per-run temp directory, `-O2 -std=c11` compilation timeout, execution watchdog timer (`SIGKILL`), `64KB` `stdout`/`stderr` truncation, and path traversal isolation against 6 malicious C payloads in `judge-malicious.test.ts` (`6/6 passing`).
6. **Business Logic (`Cat 6`)**: Verified `17:00 IST` challenge-day rollover (`SA-08`), monotonic append-only points ledger (`data-safety.test.ts`), zero points on duplicate accepted solves (`scoring.service.ts`), and blocked submissions to `DRAFT` or future-scheduled problems (`SA-05`).
7. **Rate Limits, Abuse & Cost (`Cat 7`)**: Verified `authLimiter` (20 req / 15m), `submissionLimiter` (10 req / 1m), `apiLimiter` (100 req / 1m), and bounded pagination (`limit <= 50` on public/student routes, `limit <= 100` on admin routes).
8. **Secrets, Config & Repo Hygiene (`Cat 8`)**: Verified `.gitignore` excludes `.env`, `*.db`, and keys; inspected `client/dist` bundle confirming zero private secrets (`JWT_*`, `DATABASE_URL`, `SMTP_*`) are bundled; hashed password reset tokens with `SHA-256` (`SA-04`).
9. **Dependencies & Supply Chain (`Cat 9`)**: Audited `server/package.json` and `client/package.json`; lockfiles present and deterministic builds verified.
10. **Google Drive Integration (`Cat 10`)**: Scoped strictly to user-consented `drive.file` / `drive.appdata` with automatic fallback to `localStorage` (`logicq_draft_<slug>`) when Drive is disconnected or unavailable; zero Google OAuth tokens stored in database.
11. **Privacy, Data Exposure & Compliance (`Cat 11`)**: Verified hidden test cases and other students' code are never returned in API responses; soft-retirement preserves student submission history (`SA-06`); `/.well-known/security.txt` published (`SA-07`).
12. **Admin Takeover & Insider Risk (`Cat 12`)**: Blocked admin self-ban and self-demotion (`SA-06`), enforced immediate token revocation on role change (`SA-02`), and enforced append-only audit logs in `firestore.rules`.
